# `idris-transformers` conventions

Design rules every `Transformers.*`-prefixed module in this package follows.
A new module that violates any of these is wrong; fix the module,
don't extend the convention.

## Why this package exists

idris-ml's core `Nn.Attention` (+ `TransformerBlock`) is the canonical
"build a transformer from scratch" reference. It stores attention as
`Vect numHeads (TMat headDim dModel ...)` — N tensors per QKV — because
that makes the per-head decomposition explicit in types. That's the right
design for *teaching* what a transformer is, and it round-trips its
own `.safetensors` saves cleanly.

A foreign HuggingFace checkpoint disagrees on every axis:
- HF Llama's `q_proj.weight` is **one** `[d_model, d_model]` tensor;
  idris-ml's per-head decomposition is **N** `[head_dim, d_model]`
  tensors.
- HF GPT-2's `c_attn.weight` is **one** `[d_model, 3*d_model]` tensor
  for all of Q+K+V concatenated.
- HF Llama uses `model.layers.0.self_attn.q_proj.weight`;
  idris-ml derives its param names from the `Nn.Init` scope path. The
  naming and shape conventions are different.

Bridging that gap at the *loader* — a generic
`param_load_with_remap` + `splitFusedQkv` machinery — was considered
and rejected: it carries a per-head-vs-fused split adapter forever
in C, encodes architectural decisions in C arrays, and doesn't
generalize across HF families (Llama / GPT-2 / BERT / T5 all use
different name schemes). HuggingFace's own `transformers` Python
library doesn't take that route either — every architecture is a
class whose modules match the on-disk format.

`idris-transformers` mirrors that. Each HF architecture is one
Idris module whose param names + storage shapes match HF on disk,
so loading is plain `fromPretrained` (or `load`) from
`idris-ml`'s `Checkpoint`. The module IS the adapter, expressed as
type-checked code rather than a runtime rename table.

## The conventions

### 1. Param names match HF exactly

No `_weights` plural; no underscore separators where HF uses dots.
Use HF's literal name including all dots:

```idris
-- right (Bert.idr's module-private builders take the HF prefix and
-- append HF's literal suffixes):
makeBertEmbedding "bert.embeddings.word_embeddings"   -- registers `.weight`
makeBertLinear    "bert.encoder.layer.0.attention.self.query"
                                                      -- registers `.weight` + `.bias`

-- wrong:
makeBertEmbedding "bert_embeddings_word_embeddings"
makeBertLinear    "bert_b0_attn_q"
```

Per-block prefixes are generated by tiny helpers like

```idris
encoderLayerPrefix pfx i = pfx ++ ".encoder.layer." ++ show i
```

so the per-block names are produced, not hand-typed, but the strings
themselves are HF-literal.

### 2. Storage shapes match HF on-disk

If HF stores `[d_model, d_model]` for `q_proj.weight`, the Idris
module stores the same. Per-head splits happen at **forward time** —
the attention path views the `[seq, dModel]` projection as
`[seq, nHeads, headDim]` internally (the SDPA / per-head primitives
own the split) — never at storage time.

This is the key contrast with `idris-ml/src/Ml/Nn/Attention.idr`,
which carries `Vect numHeads (TMat headDim dModel ...)` for didactic
clarity.

### 3. No new layer primitives are introduced in this package

`idris-transformers` consumes `idris-ml`'s `Ml.Nn.*` modules and
composes them. If an HF architecture needs a primitive that doesn't
exist, that primitive lands in core `idris-ml/src/Ml/Nn/` first —
RMSNorm, RoPE, and the fused-attention/GQA/SwiGLU ops (Llama's
pieces) all entered core this way. (`Transformers.KVCache` is
composition, not a primitive: a state container over core tensor
ops.)

This package's `Transformers.*` modules are *composition*, not *invention*.

### 4. One model per file

`Transformers/Bert.idr` contains the BERT encoder + pooler;
`Transformers/Gpt2.idr` GPT-2; `Transformers/Llama.idr` Llama;
`Transformers/BitNet.idr` BitNet. No cross-imports between
`Transformers.*` model modules (shared non-model plumbing —
`Transformers.Common` / `Config` / `KVCache` / `Tokenizer` — is the
exception); broadly useful helpers live in core `idris-ml`, and
model-specific ones as private definitions inside the single module.

Rationale: HF's `transformers` library has one Python file per
architecture for the same reason — variants of a single family
share enough that cross-file abstraction would obscure the
correspondence to the upstream paper. Keep each module
self-contained and skim-readable side-by-side with HF's reference
source.

### 5. Each module exposes a single smart constructor

```idris
hfBertModel : UserExecutorTraining ex => RuntimeDType dt => Linked ex => Compatible ex dt => KnownGrad g
           => {vocab, hidden, numLayers, numHeads, intermediate, maxPos, typeVocab : Nat}
           -> (paramPrefix : String)
           -> IO (BertModelState vocab hidden numLayers intermediate maxPos typeVocab ex dt g)
```

(from `Transformers/Bert.idr`; `fromPretrained` wraps it, reading the
dims from `config.json` and returning the `(cfg ** model)` dependent
pair). The constructor registers every param in creation order, so
the C registry matches the module's param-name catalogue exactly.

`paramPrefix` is typically the literal HF prefix string (e.g.
`"bert"`); the smart constructor uses it to build the full
HF-native param names internally. Callers don't hand-construct
prefixes.

### 6. The module IS the rename adapter

There is no separate translation table. Storage shape, param name,
and forward semantics are all decided together inside the module
to match HF on disk. If HF stores a fused tensor, the module stores
it fused (rule 2). If HF stores it split, the module stores it split.
A diff between an `Transformers.*` module and HF's reference Python source is
the one canonical place to look for divergence.

## Worked example — from the shipped `Transformers/Bert.idr`

The excerpts below are quoted from the live module. Config — field
names map to HF's `BertConfig` spelling 1:1:

```idris
public export
record BertConfig where
  constructor MkBertConfig
  vocabSize     : Nat
  hidden        : Nat
  numLayers     : Nat
  numHeads      : Nat
  intermediate  : Nat
  maxPosition   : Nat
  typeVocabSize : Nat  -- HF default: 2 (sentence-A / sentence-B)

||| `google/bert_uncased_L-2_H-128_A-2` — the proof-of-concept target
||| anchored by `scripts/save_oracle.py`. 2 encoder layers, hidden
||| 128, 2 attention heads (head dim 64), FFN hidden 512.
public export
bertTinyConfig : BertConfig
bertTinyConfig = MkBertConfig
  { vocabSize     = 30522
  , hidden        = 128
  , numLayers     = 2
  , numHeads      = 2
  , intermediate  = 512
  , maxPosition   = 512
  , typeVocabSize = 2
  }
```

Per-block prefixes are generated, not hand-typed:

```idris
encoderLayerPrefix pfx i = pfx ++ ".encoder.layer." ++ show i
```

The state records mirror HF's module nesting (one record per HF
submodule; `attention.self.{query,key,value}` is three separate
linears — BERT does not fuse QKV):

```idris
public export
record BertSelfAttentionState
        (hidden : Nat) (0 ex : Executor) (0 dt : DType) (0 g : GradMode) where
  constructor MkBertSelfAttn
  query : Linear hidden hidden ex dt g
  key   : Linear hidden hidden ex dt g
  value : Linear hidden hidden ex dt g

public export
record BertLayerState
        (hidden, intermediate : Nat)
        (0 ex : Executor) (0 dt : DType) (0 g : GradMode) where
  constructor MkBertLayer
  selfAttn : BertSelfAttentionState hidden ex dt g
  selfOut  : BertSelfOutputState hidden ex dt g
  intermed : BertIntermediateState hidden intermediate ex dt g
  output   : BertOutputState hidden intermediate ex dt g

public export
record BertModelState
        (vocab, hidden, numLayers, intermediate, maxPos, typeVocab : Nat)
        (0 ex : Executor) (0 dt : DType) (0 g : GradMode) where
  constructor MkBertModel
  embeddings : BertEmbeddingsState vocab hidden maxPos typeVocab ex dt g
  layers     : Vect numLayers (BertLayerState hidden intermediate ex dt g)
  pooler     : BertPoolerState hidden ex dt g
```

## Cross-references

- `packages/idris-ml/src/Ml/Checkpoint.idr` — `load` / `saveAll` /
  `fromPretrained`; consumed unchanged.
- `packages/idris-ml/src/Ml/Nn/Attention.idr` — the from-scratch
  per-head transformer (`Nn.Attention` + `TransformerBlock`); stays
  the canonical learning reference, intentionally NOT what this
  package matches.
- HuggingFace `transformers` source — the upstream truth for HF
  param names and architecture:
  - BERT: `transformers/models/bert/modeling_bert.py`
  - GPT-2: `transformers/models/gpt2/modeling_gpt2.py`
  - Llama: `transformers/models/llama/modeling_llama.py`
