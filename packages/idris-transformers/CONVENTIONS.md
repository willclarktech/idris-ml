# `idris-transformers` conventions

Design rules every `Hf*`-prefixed module in this package follows.
A new module that violates any of these is wrong; fix the module,
don't extend the convention.

## Why this package exists

idris-ml's core `Layer/Transformer.idr` is the canonical
"build a transformer from scratch" reference. It stores attention as
`Vect numHeads (LinearState ...)` — N tensors per QKV — because that
makes the per-head decomposition explicit in types. That's the right
design for *teaching* what a transformer is, and it round-trips its
own `.safetensors` saves cleanly.

A foreign HuggingFace checkpoint disagrees on every axis:
- HF Llama's `q_proj.weight` is **one** `[d_model, d_model]` tensor;
  idris-ml's per-head decomposition is **N** `[head_dim, d_model]`
  tensors.
- HF GPT-2's `c_attn.weight` is **one** `[d_model, 3*d_model]` tensor
  for all of Q+K+V concatenated.
- HF Llama uses `model.layers.0.self_attn.q_proj.weight`;
  idris-ml registers `tfm0_b0_q0_weights`. The naming and shape
  conventions are different.

Bridging that gap at the *loader* — a generic
`param_load_with_remap` + `splitFusedQkv` machinery — was considered
and rejected: it carries a per-head-vs-fused split adapter forever
in C, encodes architectural decisions in C arrays, and doesn't
generalise across HF families (Llama / GPT-2 / BERT / T5 all use
different name schemes). HuggingFace's own `transformers` Python
library doesn't take that route either — every architecture is a
class whose modules match the on-disk format.

`idris-transformers` mirrors that. Each HF architecture is one
Idris module whose param names + storage shapes match HF on disk,
so loading is plain `loadModel "model.safetensors"` from
`idris-ml`'s `Checkpoint`. The module IS the adapter, expressed as
type-checked code rather than a runtime rename table.

## The conventions

### 1. Param names match HF exactly

No `_weights` plural; no underscore separators where HF uses dots.
Use HF's literal name including all dots:

```idris
-- right:
embedding "bert.embeddings.word_embeddings.weight"
linearWb  "bert.encoder.layer.0.attention.self.query"
                              -- registers `.weight` + `.bias`

-- wrong:
embedding "bert_embeddings_word_embeddings_weights"
linear    "bert_b0_attn_q_weights"
```

Per-block prefixes are generated by tiny helpers like

```idris
bertLayerPrefix : (block : Nat) -> String
bertLayerPrefix i = "bert.encoder.layer." ++ show i
```

so the per-block names are produced, not hand-typed, but the strings
themselves are HF-literal.

### 2. Storage shapes match HF on-disk

If HF stores `[d_model, d_model]` for `q_proj.weight`, the Idris
module stores the same. Per-head reshapes happen at **forward time**
as a view (`Tensor.reshape` + `transpose` are O(1) when contiguous),
not at storage time:

```idris
-- Stored: one [d_model, d_model] linear, HF-aligned.
q : Tensor [seq, dModel] d dt g
q = qProj <> x  -- standard matmul, no per-head awareness

-- Forward-time view: reshape [seq, dModel] -> [seq, nHeads, headDim]
-- -> transpose to [nHeads, seq, headDim] for the attention math.
qHeads : Tensor [nHeads, seq, headDim] d dt g
qHeads = transpose [0, 1] (reshape q [seq, nHeads, headDim])
```

This is the key contrast with `idris-ml/src/Layer/Transformer.idr`
which carries `Vect numHeads (LinearState ...)` for didactic
clarity.

### 3. No new layer primitives are introduced in this package

`idris-transformers` consumes `idris-ml`'s `Layer.*` modules and
composes them. If an HF architecture needs a primitive that doesn't
exist (RMSNorm, RoPE, GQA, SwiGLU, KV cache — Llama's pieces), that
primitive lands in core `idris-ml/src/Layer/` first via a separate
row (Row 7 — LLM-class example owns the Llama-side primitives).

This package's `Hf*` modules are *composition*, not *invention*.

### 4. One model per file

`HfBert.idr` contains the BERT encoder + pooler. `HfGpt2.idr` will
contain GPT-2. No cross-imports between `Hf*` modules; shared
helpers live in core `idris-ml` if they're broadly useful, or as
private definitions inside the single module if they're not.

Rationale: HF's `transformers` library has one Python file per
architecture for the same reason — variants of a single family
share enough that cross-file abstraction would obscure the
correspondence to the upstream paper. Keep each module
self-contained and skim-readable side-by-side with HF's reference
source.

### 5. Each module exposes a single smart constructor

```idris
hfBertLayerAny : UserDeviceTraining d => RuntimeDType dt
              => Linked d => Compatible d dt
              => (config : BertConfig)
              -> (paramPrefix : String)
              -> IO (BertModel ... d dt WithGrad)
```

Mirrors core `idris-ml`'s `*LayerAny` pattern (`linearLayerAny`,
`transformerLayerAny`). Composable into a `Network` via `(~~>)`
without any new construction machinery.

`paramPrefix` is typically the literal HF prefix string (e.g.
`"bert"`); the smart constructor uses it to build the full
HF-native param names internally. Callers don't hand-construct
prefixes.

### 6. The module IS the rename adapter

There is no separate translation table. Storage shape, param name,
and forward semantics are all decided together inside the module
to match HF on disk. If HF stores a fused tensor, the module stores
it fused (rule 2). If HF stores it split, the module stores it split.
A diff between an `Hf*` module and HF's reference Python source is
the one canonical place to look for divergence.

## Worked example — `HfBert.idr` skeleton

```idris
module HfBert

import Layer  -- brings in Embedding, LayerNorm, Linear, Activation,
              -- Residual, etc. from core idris-ml
import Tensor
import Device
import DType.Core
import GradMode

public export
record BertConfig where
  constructor MkBertConfig
  vocabSize     : Nat
  hidden        : Nat
  numLayers     : Nat
  numHeads      : Nat
  intermediate  : Nat
  maxPosition   : Nat

||| `google/bert_uncased_L-2_H-128_A-2` config — the proof-of-concept
||| target. (Originally `prajjwal1/bert-tiny` was the target, but
||| that repo ships only `pytorch_model.bin`, no safetensors.
||| Google's L-2/H-128 publication ships both formats and shares the
||| same architectural family.)
public export
bertTinyConfig : BertConfig
bertTinyConfig = MkBertConfig
  { vocabSize = 30522
  , hidden = 128
  , numLayers = 2
  , numHeads = 2
  , intermediate = 512
  , maxPosition = 512
  }

-- Per-block prefix. Param names below are generated, not literal.
bertLayerPrefix : Nat -> String
bertLayerPrefix i = "bert.encoder.layer." ++ show i

-- One BERT encoder layer.
record BertLayerState (hidden, nHeads, intermediate : Nat)
                     (d : Device) (dt : DType) (g : GradMode) where
  constructor MkBertLayer
  -- attention.self.{query,key,value} — three separate linears,
  -- NOT fused. BERT does not fuse QKV.
  q : LinearState hidden hidden d dt g  -- `.weight`,.bias suffixes
  k : LinearState hidden hidden d dt g
  v : LinearState hidden hidden d dt g
  -- attention.output.dense + .LayerNorm
  attnOut    : LinearState hidden hidden d dt g
  attnOutLN  : LayerNormState hidden d dt g
  -- intermediate.dense + activation
  ffn1       : LinearState hidden intermediate d dt g  -- (GELU at forward)
  -- output.dense + .LayerNorm
  ffn2       : LinearState intermediate hidden d dt g
  ffnOutLN   : LayerNormState hidden d dt g

-- ...
```

(The complete module lands in a subsequent commit per the plan.)

## Cross-references

- `packages/idris-ml/src/Checkpoint.idr` — `loadModel` /
  `saveModel`; consumed unchanged.
- `packages/idris-ml/src/Layer/Transformer.idr` — the from-scratch
  per-head transformer; stays the canonical learning reference,
  intentionally NOT what this package matches.
- HuggingFace `transformers` source — the upstream truth for HF
  param names and architecture:
  - BERT: `transformers/models/bert/modeling_bert.py`
  - GPT-2: `transformers/models/gpt2/modeling_gpt2.py`
  - Llama: `transformers/models/llama/modeling_llama.py`
