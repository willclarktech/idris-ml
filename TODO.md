| idris-fmt: reflow (line-break re-layout) | infra | low | The format passes shipped to date — whitespace hygiene, import-sort, colon / `=` / `=>` alignment, reindentation — all take the author's **line breaks as given** and only adjust whitespace around them (reindentation = "breaks fixed, recompute each line's leading spaces"). **Reflow** is the categorically different operation that re-decides *where the breaks themselves go*: wrapping an over-long `f : A -> B -> C -> D` to one arg-per-line with aligned arrows, exploding a too-wide `MkRec { a, b, c }` to one field per line, joining a `do` block that now fits, or `let`/`=>`/`if` re-layout (gvnkd encodes these as policy knobs `LetStyle = Inline|Auto|Block`, `ArrowStyle = Trailing|Leading`, `IfStyle = Compact|Indented` — the knobs exist precisely because there's no single right answer; it's a layout search against a target width). **Why low-value here**: the tree is hand-laid-out and consistent, so there is nothing to reflow today (same reason reindent's rollout was 0-change). **Why high-cost / not filed higher** — and note the *corrected* reasoning: reflow's **code meaning IS already oracle-gatable** — `lex` drops `Space` and newlines are whitespace, so `codeSig` is line-break-insensitive; move breaks anywhere and `codeSig` is unchanged, with `deepSig` + `parses` catching any reflow that alters or breaks the parse. So safety-of-code is *not* the blocker. The two real blockers are: **(1) it needs a line-break decision engine** — a width model + a Wadler-style `Doc` printer (gvnkd's `PrinterM = RWS PrintCtx …`) that decides, per construct, where to break and how deep to hang the continuation. That is exactly the ~54-`PTerm`-constructor pretty-printer traversal the greenfield-printer **Route C** was chosen to avoid; reindent is cheap *because* it reuses existing breaks and never invents layout. **(2) comments are unguarded by the current oracle** — `codeSig` (and `deepSig`) drop comments by design, which is harmless for reindent (it only ever changes a comment line's leading whitespace, never its existence/position) but dangerous for reflow, the one op that **joins and splits comment-bearing lines**: a join that swallows a trailing `--` note, or a split that strands a comment on the wrong side, sails straight past the existing all-or-nothing gate.
