| Region-typed tensors: static guard for the arena/eval-scope lifetime footgun | feature | L–XL | **Filed 2026-06-17 from the linear-types design discussion.** The one tensor-level safety hole the model-linearity work doesn't close: a `Tensor` handle can outlive the arena/scope that owns its buffer → use-after-free. Both tensor P1s in this lineage were this class — `fromVect` multi-epoch (`arena_reset` on every `optimizer_step` frees the cached input across epochs) and the MNIST pre-fetched eval batch (collated batch is an arena intermediate clobbered by the next reset). **Why plain linearity is the WRONG tool** (established in the design discussion): linearity buys safety only where a runtime mutation hides behind an immutable handle whose *type doesn't change* (the `freeze`/`eval` `requires_grad` flip — the one place we use it). Tensors don't fit: (1) reverse-mode autograd *requires* fan-out — a tensor used in two graph branches must contribute to both gradients — so use-exactly-once typing is semantically wrong, not just inconvenient; (2) the actual hazard is *lifetime/scope* ("valid until the enclosing `withNoGrad`/epoch ends"), a region property, not a multiplicity property. Device/dtype/shape all dodge the footgun by being copy-with-type-change (verified: `toExecutor` is copy-semantics — host round-trip or `primIntraMigrate`, source stays valid; `tcast`/reshape likewise), so they need nothing. **The right mechanism**: region/scope types — a rank-2 `runST`-style bracket where tensors carry an erased region phantom (`Tensor dims ex dt g rgn`) that can't escape its `withRegion`/`withNoGrad`/epoch scope (the classic `forall s. ST s a` trick), or a lighter borrow discipline (use freely within a scope, can't retain past it). Success criterion: a tensor captured before an `arena_reset` / outside its eval bracket and used afterward fails to *elaborate*, replacing the current runtime/discipline mitigations. **Current mitigations (all reactive, not static)**: IO-typed op surface (forces explicit ordering), the wrapped-handle ABI + `idris-tensor-guardian` refcounting (mlx), `withNoGrad`/`withGenFree` brackets, and the `Dataset { item : Fin n -> IO sample }` rule (materialise fresh, never cache device tensors). **Cost / why L–XL**: rank-2 region phantoms thread awkwardly through a library this size (every op + every layer signature gains a region param; interop with the region-free surface must stay zero-cost opt-in, same constraint as the named-axis row); mind the type-level-Nat elaboration gotchas. Plausibly its own plan-mode session ending in a prototype on one vehicle (the `fromVect`→`batched`→`fit` loop is the natural target — it's the exact P1 repro). Cross-refs: CHANGELOG `fromVectIO` (P1 fix `65a161e1`) + the MNIST P1 (arena recycle + eval-batch lifetime, 2026-06-17); `backend_tape/arena.c` (`arena_reset`/`arena_free_all`); `Tensor.idr` (`withNoGrad`/`withGenFreeL`/`ioRerun`); `docs/develop/tensor-lifecycle.md`; `Dataset.idr` (`fromVectIO`/`fromIndexed`).
