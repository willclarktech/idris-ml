Tape dtype parity — F32 trainable + 8 inference dtypes via the unified dispatch (closed 2026-05-23):
- Tape backend (`packages/backends/backend_tape.c`) is no longer F64-only. F32 ships as a real training dtype (4-byte-per-elem float storage, dedicated kernels, autograd grads still F64); BF16, F16, I8/I16/I32/I64, U8, Bool ship as inference-only storage via the `double` lingua franca (rounded through the dtype's representable precision on construct + cast, never trainable). `Compatible TapeDev <dt>` is open Idris-side for all 10 dtypes (`Device/Tape.idr`).
- F32 storage path: `tape_arena_f32_from_doubles` / `tape_persistent_f32_from_doubles` allocate real `float*` buffers; `tape_load_d` / `tape_store_d` are the dtype-aware element accessors that branch on `dtype_tag`. The `backend_tape_kernels.inc` X-macro stamps the binop + unop elementwise bodies once for F64 and once for F32 (`SCALAR=double` vs `SCALAR=float`); the four "rungs" — elementwise / matmul (`tensor_mv` + OP_MV backward) / softmax / optimizer step — were each test-gated by a `TAPE_F32_SKIP_*` flag in T29's gradcheck oracle ladder, un-skipped one at a time as the rung came online. Phase 3b extended the same per-kernel pattern (paired RED→GREEN commits, no `.inc` extension required) to the remaining ~50 non-elementwise kernels: scalar/reduction ops, reshape/concat/select/view, losses (MSE/CE/BCE/NLL), BLAS-heavy linalg (matmul/linear/bmm/outer/vecmat — `cblas_s{gemm,gemv,ger}` variants), normalization + conv + pool, lookups (embedding/gather/scatter/argsort/cumprod), and recurrent cells (LSTM/GRU/cosine_sim). End state: every public `tensor_*` accepts F32 input without abort.
- Asymmetric design choice: `data = F32`, `grad = F64`. Lets the entire 67-case backward switch stay dtype-agnostic for grad reads/writes (`((double*)t->grad)[i]` everywhere); only data *reads* in the ~12 backward cases that touch input data needed `tape_load_d`. The torch invariant "param dtype == grad dtype" is deliberately not preserved on tape; mixed-precision (BF16/F16 trainable + GradScaler/autocast) is filed as a separate TODO row.
- Inference dtypes: T31 unit block exercises every dtype's create/cast/readback round-trip. Half-precision (BF16/F16) uses the bit helpers lifted from `safetensors.c:69-122` (`bf16_bits_to_double` / `double_to_bf16_bits` / `f16_bits_to_double` / `double_to_f16_bits`) to `shared_utils.{c,h}` so safetensors I/O and `tape_round_to_dtype`'s DT_BF16 / DT_F16 arms share one rounding implementation; bf16's nearest-of-0.1 is 0x3DCD (0.10009765625, rounds UP); f16's is 0x2E66 (0.0999755859375). Integer dtypes round through plain casts (exact within range; I64 above 2^53 inherits the lingua-franca caveat filed under row 20).
- Cast path: `tensor_cast_dtype_streamed` for dtag=0 (F32 target) now produces real float storage matching the Phase 3 streamed-create path. Earlier it routed through `tape_retag_round`, retagging double storage to DT_F32 without narrowing — a "fake F32" that conflicted with `tensor_to_doubles` / `tape_load_d` / kernel paths (all assume 4-byte-per-elem float storage). Type-safe integral index API — targsort / tgather / tscatterAdd (closed 2026-05-22):
- New typed surface in `Tensor.idr`: `targsort` returns an `I64`-dtyped index tensor (`Tensor dims d I64 NoGrad`), and `tgather` / `tscatterAdd` take an `IsIntegral` index. "These are indices, not reals" is now captured in the type instead of riding in a float dtype. The untyped `primArgsort` / `primGather` / `primScatterAdd` stay — `Layer/Dnc.idr` still uses them on its F64 path, which runs on every backend and can't spell an integral index.
- **Torch-only by construction, not by a backend check.** An integer-dtyped tensor only exists where `Compatible d I64` holds — `TorchDev TCpu` / `TCuda`. Metal has no F64/int (`TMps` has no I64 instance) and tape/mlx store F64 only, so calling `targsort` there is a *type error*, not a runtime dtype mismatch. This was the chosen scope (torch-only typed surface now); all-backend availability follows the separate "Broaden tape backend dtype storage" row, with no change needed to this surface when it lands.
- C change (torch only): `tensor_argsort` now materializes its permutation in `kLong` (integral) instead of `.to(kFloat64)`. This is what the typed `I64` result rests on, and it fixes two latent bugs the float cast carried — precision loss above 2^53 indices, and an MPS abort (`.to(kFloat64)` on Metal, which has no F64). `gather` / `scatter_add` already coerce their index to `kLong` internally, so the untyped DNC path is unaffected (it now threads honest integer indices through torch). tape (`double`) / mlx (`astype(float32)`) argsort are untouched — they have no integer storage.
- **Rejected approach stayed rejected**: argsort's output is *not* cast to the input float dtype (that silently rounds indices on low-mantissa dtypes — BF16 is exact only to 256). The cast is to `I64`, the type-safe direction.
- Verification: `make BACKEND=torch test-backend` adds a torch-gated `argsort result is integral (I64)` assertion (alongside the unchanged value checks, which read back identically through `tensor_to_doubles`); `make example-index-ops` (`Example.IndexOps`, torch-only, excluded from the all-backend ipkg like `DTypeSerialize`) runs the typed `targsort → tgather → tscatterAdd` pipeline end to end with order-sensitive readouts (gather sorted-dot 29.0, scatter placement-dot 18.5). `make test-backend-tape` confirms no tape regression.

SafeTensors bf16/f16 + integer byte-level I/O (closed 2026-05-22):

- `scripts/perf-sweep.sh` and `scripts/perf-baseline.sh` ran the example binary with `>/dev/null 2>&1` and discarded its exit code, so a binary that aborted mid-training had its time-to-abort billed as a legitimate measurement.
